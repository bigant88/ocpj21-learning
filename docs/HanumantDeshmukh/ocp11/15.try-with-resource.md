# Resource Management trong Java (Tóm tắt)
## 1. Resource là gì?
- Resource = các nguồn dữ liệu bên ngoài:
    - File
    - Database connection
    - Network stream
- Resource **không được JVM tự thu hồi** như object bình thường
---
## 2. Quy trình làm việc với Resource
Làm việc với resource **luôn gồm 3 bước**:
1. **Open** resource
2. **Use** resource (read / write / process)
3. **Close** resource
⚠️ Quên đóng resource ⇒ **resource leak**
---
## 3. Hậu quả của Resource Leak
- Resource trở nên **không truy cập được**
- Ví dụ:
    - Không mở được file
    - Không kết nối được database
    - Ứng dụng khác cũng bị ảnh hưởng
---
## 4. Quản lý Resource kiểu truyền thống (try–catch–finally)
```java
FileInputStream is = null;
try {
    is = new FileInputStream("myfile.txt"); // open
    // read file
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (is != null) {
        try {
            is.close(); // close
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```
- Code dài
- Dễ quên đóng resource
## 5 Try-with-resources (Khuyến nghị)
```java
try (FileInputStream is = new FileInputStream("file.txt")) {
    // use resource
} catch (IOException e) {
    e.printStackTrace();
}
```
- Resource tự động đóng ở cuối block try
- JVM sinh ra finally ngầm
- Resource phải implement AutoCloseable
## 6 Nhiều Resource trong try-with-resources
```java
try (
    MyFileClass r1 = new MyFileClass(1);
    MyFileClass r2 = new MyFileClass(2)
) {
    throw new RuntimeException();
}
```
- MyFileClass phải implement AutoCloseable 
- Thứ tự đóng resource : r2 -> r1 . ➡️ Ngược với thứ tự khai báo
- Resource đóng trước catch
- Resources are not even accessible in the catch or finally block
- Resources are closed even if the code in the try block throws an exception.
- java.lang.AutoCloseable's close() throws Exception but java.io.Closeable's close() throws IOException.


## 7 Suppressed Exceptions (Try-with-resources)

### Khái niệm
- **Suppressed Exception** xảy ra khi:
    - `try-with-resources` **ném ra một exception trong khối try**
    - **đồng thời** phương thức `close()` của resource **cũng ném exception**
- Khi đó:
    - **Chỉ exception đầu tiên (primary exception) được catch**
    - Các exception còn lại (từ `close()`) sẽ bị **suppressed**

---

## Ví dụ: close() ném Exception

```java
public class Door implements AutoCloseable {
    @Override
    public void close() throws IllegalStateException {
        throw new IllegalStateException("The door does not close");
    }
}
```
##  Ví dụ sử dụng trong try-with-resources
```java
public static void main(String[] args) {
    try (Door d = new Door()) {
        throw new IllegalStateException("Something is wrong");
    } catch (IllegalStateException e) {
        System.out.println("caught: " + e.getMessage());

        for (Throwable t : e.getSuppressed()) {
            System.out.println("suppressed: " + t.getMessage());
        }
    }
}
//Output: caught: Something is wrong
//suppressed: The door does not close
```
### Thứ tự xảy ra Exception :
- 1. Exception trong try xảy ra trước  → Primary Exception
- 2. JVM gọi close() để đóng resource 
- 3. close() ném exception → Suppressed Exception
- 4. Chỉ primary exception được catch
- 5. Exception từ close() bị đẩy vào danh sách suppressed
### Ghi nhớ:
- Resource luôn đóng trước catch
- Exception trong close() không ghi đè exception chính
- Suppressed exception không bị mất, chỉ bị ẩn đi
