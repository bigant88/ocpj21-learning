## ✅ Điểm bẫy OCP
- IOException: hầu hết các phương thức NIO ném checked exception.
- createDirectories() khác với createDirectory() (cái sau lỗi nếu tồn tại).
- readAllLines() tải toàn bộ vào bộ nhớ → có thể gây OOM với file lớn.
- walk() và find() trả về Stream<Path> → cần đóng bằng try-with-resources.
- mismatch() trả về long, không phải int.
## 1. Xóa file
- deleteIfExists(Path path) → trả về boolean, ném IOException.
- delete(Path path) → void,  ném IOException.
## 2. Duyệt thư mục
- list(): Liệt kê một cấp (flat listing). Trả về Stream<Path>.
```java
try (Stream<Path> stream = Files.list(tmp)) { ... }
```
- find(): Tìm file với điều kiện, có maxDepth.
```java
Files.find(start, maxDepth, (p, attr) -> attr.isRegularFile());
```
- walk(): Duyệt đệ quy tất cả thư mục con.
## 3. Tạo thư mục
- createDirectories() → không lỗi nếu thư mục đã tồn tại.
- createDirectory(): lỗi nếu đã tồn tại
```java
var dir = Path.of("/flip");
dir = Files.createDirectories(dir);
```
- ⚠️ Không dùng mkdir() trong NIO.

## 4. Đọc file
- readAllLines(): Trả về List<String> (toàn bộ nội dung vào bộ nhớ) -> có thể gây OOM
```java
List<String> lines = Files.readAllLines(path);
```
- lines(): Trả về Stream<String> (đọc theo luồng).

## 5. So sánh file
- isSameFile(): Kiểm tra hai Path trỏ đến cùng file.
```java
Files.isSameFile(p1, p2);
```
- mismatch(): Trả về vị trí byte đầu tiên khác nhau, hoặc -1 nếu giống nhau.
```java
long pos = Files.mismatch(path1, path2);
```
