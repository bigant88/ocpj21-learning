# Files
## ✅ Điểm bẫy OCP
- IOException: hầu hết các phương thức NIO ném checked exception.
- createDirectories() khác với createDirectory() (cái sau lỗi nếu tồn tại).
- readAllLines() tải toàn bộ vào bộ nhớ → có thể gây OOM với file lớn.
- walk() và find() trả về Stream<Path> → cần đóng bằng try-with-resources.
- mismatch() trả về long, không phải int.
## 1. Xóa file
- deleteIfExists(Path path) → trả về boolean, ném IOException.
- delete(Path path) → void,  ném IOException.
## 2. Duyệt thư mục
- list(): Liệt kê một cấp (flat listing). Trả về Stream<Path>.
```java
try (Stream<Path> stream = Files.list(tmp)) { ... }
```
- find(): Tìm file với điều kiện, có maxDepth.
```java
Files.find(start, maxDepth, (p, attr) -> attr.isRegularFile());
```
- walk(): Duyệt đệ quy tất cả thư mục con.
## 3. Tạo thư mục
- createDirectories() → không lỗi nếu thư mục đã tồn tại.
- createDirectory(): lỗi nếu đã tồn tại
```java
var dir = Path.of("/flip");
dir = Files.createDirectories(dir);
```
- ⚠️ Không dùng mkdir() trong NIO.

## 4. Đọc file
- readAllLines(): Trả về List<String> (toàn bộ nội dung vào bộ nhớ) -> có thể gây OOM
```java
List<String> lines = Files.readAllLines(path);
```
- lines(): Trả về Stream<String> (đọc theo luồng).

## 5. So sánh file
- isSameFile(): Kiểm tra hai Path trỏ đến cùng file.
```java
Files.isSameFile(p1, p2);
```
- mismatch(): Trả về vị trí byte đầu tiên khác nhau, hoặc -1 nếu giống nhau.
```java
long pos = Files.mismatch(path1, path2);
```

# Java I/O API - NIO 2
## I/O vs NIO vs NIO.2
| API       | Package         | Đặc điểm                     |
| --------- | --------------- | ---------------------------- |
| I/O (cũ)  | `java.io`       | Stream-based, blocking       |
| NIO (1.4) | `java.nio`      | Buffer + Channel             |
| **NIO.2** | `java.nio.file` | File system, Path, Files |
- OCP tập trung chủ yếu vào NIO.2
## Path – trung tâm của NIO.2 (RẤT QUAN TRỌNG)
- Tạo Path 
```java
Path p1 = Path.of("data/file.txt");          // Java 11+
Path p2 = Paths.get("data", "file.txt");     // legacy
```
- Absolute vs Relative
```java
p.isAbsolute();   // true / false
p.toAbsolutePath();
```
- Bẫy thi:
  - normalize() không kiểm tra file có tồn tại
  - toRealPath() có kiểm tra và có thể throw IOException
- normalize()
```java
Path p = Path.of("a/../b/./c");
System.out.println(p.normalize()); // b/c
```
- resolve() & relativize()
```java
Path base = Path.of("/home/user");
Path child = Path.of("docs/file.txt");

base.resolve(child);        // /home/user/docs/file.txt
base.relativize(child);     // ❌ IllegalArgumentException
```

- Rule: relativize() → cả hai phải cùng absolute hoặc cùng relative

## Path.resolve() vs Path.relativize()

| Method        | Ý nghĩa                                 | Dùng khi |
|---------------|------------------------------------------|----------|
| `resolve()`   | Ghép đường dẫn                           | Có base path và muốn thêm một phần nữa |
| `relativize()`| Tính đường đi tương đối giữa hai path    | Muốn biết từ path A đến path B đi như nào |
---
## 1️⃣ resolve() — Ghép đường dẫn
### Quy tắc
- Nếu `path2` là **absolute path** → kết quả **CHÍNH LÀ path2**
- Nếu `path2` là **relative path** → kết quả là `path1 + path2`
### Ví dụ
```java
Path base = Paths.get("/home/user");
Path p1 = base.resolve("documents");
// → /home/user/documents
Path p2 = base.resolve("/etc/config");
// → /etc/config  (vì absolute)

## Files – thao tác file & thư mục
- Kiểm tra file
```java
Files.exists(path); // có thể return false nếu không có quyền
Files.notExists(path);
Files.isDirectory(path);
Files.isRegularFile(path);
Files.isReadable(path);
```
- Tạo & xóa
```java
Files.createFile(path);
Files.createDirectory(path);
Files.createDirectories(path);

Files.delete(path);            // throw exception
Files.deleteIfExists(path);    // boolean
```
- Copy / Move (RẤT HAY RA)
```java
Files.copy(src, dest);
Files.move(src, dest);
```
- Copy directory → không copy nội dung
- Move directory → move toàn bộ
- CopyOptions
```java
StandardCopyOption.REPLACE_EXISTING
StandardCopyOption.ATOMIC_MOVE   // chỉ cho move
```
## Đọc / ghi file (OCP hay hỏi)
- Đọc nhanh: Tốn RAM – đọc toàn bộ file
```java
List<String> lines = Files.readAllLines(path);
```
- Stream-based (ưu tiên)
```java
try (Stream<String> s = Files.lines(path)) {
    s.forEach(System.out::println);
}
```
- Ghi file
```java
Files.write(path, List.of("a", "b"));
StandardOpenOption.CREATE
StandardOpenOption.APPEND
StandardOpenOption.TRUNCATE_EXISTING
```
## DirectoryStream vs Files.walk()
- DirectoryStream (nhẹ)
```java
try (DirectoryStream<Path> ds =
     Files.newDirectoryStream(dir)) {
    for (Path p : ds) {
        System.out.println(p);
    }
}
```
- Files.walk() (RẤT HAY RA)
```java
try (Stream<Path> s = Files.walk(dir)) {
    s.filter(Files::isRegularFile)
     .forEach(System.out::println);
}
// walk() → recursive
// list() → không recursive
```
## Exception hay gặp
| Method                | Exception                    |
| --------------------- | ---------------------------- |
| `toRealPath()`        | `IOException`                |
| `createFile()`        | `FileAlreadyExistsException` |
| `delete()`            | `NoSuchFileException`        |
| `newBufferedReader()` | `IOException`                |

## Bẫy OCP hay gặp
- normalize() có kiểm tra file tồn tại? -> Không
- resolve() với absolute path?
```java
Path a = Path.of("/a");
Path b = Path.of("/b");

a.resolve(b); // /b
```
- relativize() khác loại? -> Runtime exception
- Files.lines() có cần close? -> Có (AutoCloseable)

## Cách học NIO.2 để đỗ OCP
- Thuộc Path methods
- Phân biệt:
  - normalize() vs toRealPath()
  - list() vs walk()
- Nhớ exception behavior
- Hiểu copy / move options
