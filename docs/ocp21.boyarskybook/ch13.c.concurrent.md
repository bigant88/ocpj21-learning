# 1. CONCURRENT COLLECTIONS
## 1. Vì sao cần Concurrent Collections?
- Khi nhiều thread cùng đọc/ghi một collection, có thể xảy ra:
  - ❌ Memory Consistency Error
  - ❌ ConcurrentModificationException
  - ❌ Dữ liệu bị sai hoặc không nhất quán
- Ví dụ: 
```java
var foodData = new HashMap<String, Integer>();
foodData.put("penguin", 1);
foodData.put("flamingo", 2);

for (String key : foodData.keySet())
   foodData.remove(key);   // Lỗi runtime
// ➡️ Nguyên nhân: Iterator của HashMap không cho phép sửa collection khi đang duyệt.
```
- Cách sửa đúng: 
```java
var foodData = new ConcurrentHashMap<String, Integer>();
```
## 2 Khi nào PHẢI dùng Concurrent Collections?
- Luật vàng trong tài liệu:
> Nếu nhiều thread cùng modify collection và không dùng synchronized, thì PHẢI dùng concurrent collection.

- Không cần concurrent collection khi:
  -  Collection immutable
  - Các phần tử bên trong immutable
  - Immutable → thread-safe tự nhiên
## 3. Các Concurrent Collection quan trọng (CỰC KỲ HAY THI)
| Class                   | Kiểu  | Sorted | Blocking |
| ----------------------- | ----- | ------ | -------- |
| `ConcurrentHashMap`     | Map   | ❌      | ❌        |
| `ConcurrentLinkedQueue` | Queue | ❌      | ❌        |
| `ConcurrentSkipListMap` | Map   | ✅      | ❌        |
| `ConcurrentSkipListSet` | Set   | ✅      | ❌        |
| `CopyOnWriteArrayList`  | List  | ❌      | ❌        |
| `CopyOnWriteArraySet`   | Set   | ❌      | ❌        |
| `LinkedBlockingQueue`   | Queue | ❌      | ✅        |
- Mẹo nhớ nhanh cho đề thi
  - Skip → collection có sắp xếp (sorted)
  - BlockingQueue → có thể chờ (block)
## 4. CopyOnWrite Collections (rất hay ra đề)
- Cách hoạt động: 
  - Mỗi lần add / remove / update ➜ Tạo bản sao mới của collection
  - Iterator không bị ảnh hưởng
```java
List<Integer> favNumbers = new CopyOnWriteArrayList<>(List.of(4, 3, 42));

for (var n : favNumbers) {
   System.out.print(n + " ");   // 4 3 42
   favNumbers.add(n + 1);
}

System.out.println("Size: " + favNumbers.size()); // 6
```
- Tốn bộ nhớ
- Dùng khi : Đọc nhiều – ghi ít
## 5. Concurrent Collection vs Synchronized Collection
```java
ConcurrentHashMap
CopyOnWriteArrayList
// Tạo mới collection → dùng concurrent class
```
```java
List<Integer> list = Collections.synchronizedList(new ArrayList<>());
//Nhận collection có sẵn → dùng Collections.synchronizedX()
```
# 2 IDENTIFYING THREADING PROBLEMS
## Liveness
- Liveness là khả năng của chương trình tiếp tục chạy và phản hồi trong thời gian hợp lý 
- Liveness Problem: chương trình bị "kẹt", không tiến triển 
- 3 loại: 
  - Deadlock 
  - Starvation
  - Livelock 
## Deadlock 
- Deadlock xảy ra khi:
  - ≥ 2 thread
  - Bị block vĩnh viễn
  - Mỗi thread chờ resource mà thread khác đang giữ -> BLOCKED forever 
- Ví dụ: 
```java
synchronized(food) {
   synchronized(water) { }
}
// Foxy giữ food, chờ water
```
```java
synchronized(water) {
   synchronized(food) { }
}
// Tails giữ water, chờ food
```
- Dấu hiệu nhận biết deadlock trong đề thi
  - synchronized lồng nhau
  - Lock khác thứ tự
  - Nhiều resource (A → B và B → A)
## Starvation
- 1 thread luôn bị từ chối resource
- Các thread khác luôn giành được lock trước
- Thread vẫn hoạt động, nhưng không bao giờ hoàn thành

## Livelock
- ≥ 2 thread
- Vẫn đang chạy
- Nhưng lặp lại cùng một hành vi mãi mãi
- Không thread nào hoàn thành công việc
- Thread active nhưng không progress
- So sánh nhanh

  | Vấn đề     | Thread có chạy? | Có tiến triển? |
  | ---------- | --------------- | -------------- |
  | Deadlock   | ❌ Không         | ❌              |
  | Starvation | ✅ Có            | ❌              |
  | Livelock   | ✅ Có            | ❌              |

## Race Condition
- Race condition xảy ra khi:
  - Các tác vụ đáng lẽ phải chạy tuần tự
  - Lại chạy đồng thời
  - ➜ Kết quả không mong muốn
- Mối liên hệ giữa Race Condition & Thread Safety
  - Race condition là hậu quả
  - Thread-safety là giải pháp
- 📌 Nếu thấy:
```java
++variable
shared mutable state
```
- → Nghĩ ngay: race condition
